# 山線 (WL-M) 實作問題總結報告

## 實作日期
2026-01-24

## 概述
本次實作西部幹線山線 (竹南-彰化) 過程中，發現多項流程和資料問題。本報告整理這些問題，作為後續改進標準流程的參考。

---

## 問題分類

### 1. 資料來源問題

#### 問題描述
目前流程從 TDX API 取得軌道資料，但資料可能不完整或有缺口。

#### 具體案例
- 海線 (WL-C) 從 TDX 取得的軌道是 MultiLineString，有 65km 的斷裂缺口
- 山線雖然資料完整，但部分路段有繞路問題（如后里-泰安段）

#### 建議改進
- **改用 Optra 備份資料**：從 `all_tracks_backup.geojson` 取得軌道資料
- 優點：資料已經過驗證，較為完整
- 流程調整：先檢查 Optra 備份，若無再考慮 TDX

---

### 2. 車站編號重複問題

#### 問題描述
同一個車站存在新舊兩套編號，導致地圖上顯示重複的站點。

#### 具體案例
| 舊編號 | 新編號 | 車站名稱 |
|--------|--------|----------|
| 3250 | 3240 | 潭子 |
| 3260 | 3243 | 頭家厝 |
| 3270 | 3245 | 松竹 |
| 3280 | 3247 | 太原 |
| 3290 | 3249 | 精武 |
| 3340 | 3325 | 新烏日 |
| 3350 | 3330 | 成功 |

#### 根本原因
- `stations_snapped.geojson` 中同時包含舊編號和新編號的車站資料
- 新增車站時未檢查是否已有對應的舊編號存在

#### 建議改進
- **建立車站編號對照表**：明確定義每個車站的正式編號
- **新增車站前檢查**：檢查是否有同名或近距離的車站已存在
- **自動化驗證腳本**：檢測距離過近 (<100m) 的車站對

---

### 3. 車站名稱標記錯誤

#### 問題描述
部分車站的 `name` 和 `name_zh` 欄位被錯誤標記。

#### 具體案例
| station_id | 錯誤名稱 | 正確名稱 |
|------------|----------|----------|
| 3240 | 栗林 | 潭子 |
| 3310 | 五權 | 大慶 |
| 3320 | 大慶 | 烏日 |
| 3330 | 烏日 | 成功 |

#### 根本原因
- 手動新增車站時複製貼上錯誤
- 沒有與官方車站資料進行交叉驗證

#### 建議改進
- **使用官方車站資料**：從 TDX 或 Optra 取得正確的車站名稱
- **建立驗證機制**：新增車站後自動與官方資料比對名稱

---

### 4. 車站座標未投影到軌道

#### 問題描述
車站座標沒有精確投影到軌道上，導致列車停靠位置與顯示站點不一致。

#### 具體案例
- 精武站：原座標距離軌道約 1.3km
- 松竹站：原座標偏離軌道約 1km
- 多個車站需要手動提供正確座標

#### 根本原因
- 直接使用 TDX 的車站座標，未進行軌道投影
- 部分車站座標是建築物位置，不是月台位置

#### 建議改進
- **自動投影流程**：車站座標自動投影到最近的軌道點
- **投影距離檢查**：若投影距離 > 50m，標記為需人工確認
- **使用月台座標**：優先使用 Optra 中已投影的車站座標

---

### 5. 軌道路徑繞路問題

#### 問題描述
部分軌道路段有不合理的繞路，需要手繪修正。

#### 具體案例
| 路段 | 問題描述 |
|------|----------|
| 后里-泰安 | 軌道有來回繞行，增加約 3km 不合理路徑 |
| 新烏日-烏日 | 軌道有錯誤連接，產生異常折線 |

#### 根本原因
- TDX 軌道資料品質問題
- 可能是多條軌道合併時產生的錯誤

#### 建議改進
- **軌道品質檢查**：偵測軌道中的急轉彎 (>90°) 或回頭路段
- **手繪模板自動生成**：標記問題路段的起終點，方便手繪
- **保留手繪軌道**：手繪完成的軌道段落存入 `tracks_handdrawn/` 供複用

---

### 6. 跨路線車站不一致

#### 問題描述
同一個實體車站在不同路線使用不同的 station_id。

#### 具體案例
- 成功站：山線用 `3330`，成追線用 `3350`
- 導致兩條路線的成功站顯示在不同位置

#### 根本原因
- 歷史編號系統遺留問題
- 新增路線時未檢查共用車站

#### 建議改進
- **建立共用車站對照表**：定義哪些路線共用哪些車站
- **統一 station_id**：同一實體車站只用一個 ID
- **O-D 軌道起終點同步**：確保共用車站的座標一致

---

### 7. 進度值更新遺漏

#### 問題描述
車站座標或軌道修正後，忘記重新計算 `station_progress` 值。

#### 具體案例
- 修正精武站座標後，進度值仍是舊值
- 合併手繪軌道後，部分車站進度值未更新

#### 建議改進
- **自動化進度值計算**：任何車站或軌道變更後自動重算
- **驗證腳本**：檢查進度值是否與車站座標一致

---

## 建議的改進流程

### 新增路線標準流程 (修訂版)

```
1. 資料準備
   ├─ 優先從 Optra 備份取得軌道資料
   ├─ 若無則從 TDX 取得
   └─ 檢查軌道類型 (LineString vs MultiLineString)

2. 軌道品質檢查
   ├─ 偵測大跳躍 (> 1km)
   ├─ 偵測急轉彎 (> 90°)
   ├─ 偵測回頭路段
   └─ 標記需手繪的路段

3. 車站資料處理
   ├─ 從官方資料取得車站清單和名稱
   ├─ 檢查是否有重複編號
   ├─ 檢查是否有共用車站 (跨路線)
   └─ 投影車站座標到軌道

4. 投影驗證
   ├─ 檢查投影距離 (> 50m 需人工確認)
   ├─ 檢查車站順序是否正確
   └─ 生成問題車站報告

5. 手繪修正 (如需要)
   ├─ 生成手繪模板
   ├─ 人工手繪問題路段
   └─ 合併手繪軌道

6. 進度值計算
   ├─ 計算所有車站的 progress 值
   ├─ 驗證進度值順序正確
   └─ 更新 od_station_progress.json

7. 同步更新
   ├─ O-D 軌道
   ├─ Golden Track (顯示用)
   └─ 共用車站的其他路線
```
