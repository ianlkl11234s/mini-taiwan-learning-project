## 系統架構理解

```
┌─────────────────────────────────────────────────────────────┐
│                    TRA 雙軌道系統                            │
├─────────────────────────────────────────────────────────────┤
│  【顯示軌道】                    【行駛軌道】                 │
│  all_tracks.geojson 或           tracks_od/                 │
│  tracks_golden/                                             │
│                                                             │
│  用途: 地圖底圖線條               用途: 列車位置計算          │
│  特點: 大家黏在一起的完整路網     特點: 分段的 O-D 軌道       │
│                                                             │
│  這兩者【完全獨立】                                           │
└─────────────────────────────────────────────────────────────┘
```

**核心概念**：
- **行駛軌道**：分段的 O-D 軌道，必須正確（列車位置計算用）
- **顯示軌道**：可以是合併的大底圖，或行駛軌道也同時顯示

**列車運行流程**：
1. 時刻表指定 `od_track_id`（如 `NW-HC-NB`）
2. 引擎從 `tracks_od/` 載入該 O-D 軌道
3. 根據 `od_station_progress.json` 計算列車在軌道上的位置
4. 3D 模型渲染在該位置

**地圖顯示流程**：
1. 前端從 `tracks_golden/` 或 `tracks_official/` 載入顯示軌道
2. 用 Mapbox 渲染軌道線條
3. 與列車位置計算完全獨立

## 重建計畫

### 工作流程（每段軌道）

```
對每一段 O-D 軌道：
1. 決定區段範圍（例如：臺北→花蓮）
2. 檢查 all_tracks_backup.geojson 中該段品質 ← 實作時確認
3. 如果品質 OK → 直接提取作為行駛軌道
   如果有問題 → 手繪修正後再提取
4. 建立行駛軌道 (tracks_od/)
5. 計算車站進度 (od_station_progress.json)
6. 【關鍵】發一班車實際測試：
   - 讓列車從起點走到終點
   - 確認列車位置正確、無跳動
   - 確認停靠站位置正確
7. 測試通過後，才進入時刻表整合
8. 進入下一段
```

## 驗證方法

每段 O-D 軌道完成後，立即進行測試：

### 快速測試（建立軌道後）
1. **發一班測試車**：用簡易時刻表讓一台車跑完全程
2. **觀察列車位置**：列車應該沿著行駛軌道平穩移動
3. **確認無跳動**：沒有座標跳躍造成的瞬移

### 完整測試（時刻表整合前）
1. **軌道驗證**：檢查無座標跳躍 (>500m)
2. **視覺驗證**：行駛軌道設為半透明，確認列車走在軌道上
3. **停靠驗證**：列車在每個車站正確停靠
